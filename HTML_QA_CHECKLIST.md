# 12 static HTML checks to run before publishing a page

Use this practical checklist before shipping a static HTML page. It focuses on source-level issues that affect search previews, accessibility and basic quality.

1. **Declare the document language.** Start with `<html lang="en">` or the language that matches the page.
2. **Use one descriptive title.** Keep the `<title>` specific to the page rather than the whole site.
3. **Write a real meta description.** Describe the page in natural language; avoid repeating the title word for word.
4. **Set the viewport.** Most pages need `<meta name="viewport" content="width=device-width, initial-scale=1">`.
5. **Use one clear H1.** A visitor should understand the page's main job from its H1.
6. **Keep heading order logical.** Do not jump from H1 straight to H4 for visual styling.
7. **Give meaningful images alt text.** Informative images need an explanation; purely decorative images can use empty alt text.
8. **Label form controls.** A visible label or programmatic label is needed for inputs, selects and textareas.
9. **Check link text.** “Read more” is weak by itself; name the destination or outcome.
10. **Set a canonical URL for public pages.** This helps search engines identify the preferred version.
11. **Add Open Graph basics.** Title, description and canonical URL make shared links clearer.
12. **Inspect the final source.** Verify that styles, scripts, metadata and language attributes are actually present in the shipped HTML.
